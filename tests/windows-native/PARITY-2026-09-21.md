## Defects and fixes

Windows background processes inherited or allocated consoles. DearMachine now
creates its detached supervisor and managed descendants without console windows.
The installer and concierge also request hidden Windows process launches for
their shell tools. A native loopback-provider test reproduces the latter defect
by launching PowerShell through each actual agent and observing its console
handle, rather than only inspecting spawn options.

Closing a Windows SSH session killed the supervisor through OpenSSH's session
job. The supervisor now requests breakaway only when the enclosing job permits
it. The native regression uses the observed session-job flags; separate tests
retain cancellation ownership of workers. Jobs which forbid breakaway remain
an explicit platform boundary.

Sendmux previously refused Windows because the Unix directory durability
barrier had no Windows implementation. Windows submission journals now use
SQLite with PERSIST journaling and EXTRA synchronization, retaining the
cross-process lock across provider calls. Existing JSON journals migrate only
when the database has no saved submission. Tests cover private database and
sidecar permissions, unsafe paths, migration, concurrency and uncertain sends.
The Unix journal protocol is unchanged.

The abrupt-restart fixture writes an uncertain submission and its attempted-send
marker, then waits. The test terminated only its dedicated VM's hypervisor,
restarted the same virtual disk, and verified the exact saved state. This is
evidence for recovery after abrupt VM termination; it does not certify physical
storage hardware against power loss.

The credential-boundary scanner had decoded only the first Zstandard frame of
an appended trajectory. It now iterates every compressed frame and validates
every decoded JSONL record. A counterfeit credential deliberately placed in a
later frame verifies that the scan includes it. The recovered native installer
trajectory was independently decoded in full and scanned against the registered
credentials and their encoded forms; none were found.

A later setup retry reproduced a shared-store recovery defect after OMP had
saved a custom backend credential. The model host accepted only its own provider
variables when writing the shared file; assistant sign-out could also discard
backend entries. Installer `a84bf4e` preserves the credential adapter's generated
backend namespace during writes and removals, while rejecting unrelated
assignments without rewriting the store. Both regressions failed before the fix
and pass in the full unit suite. The native counterfeit fixture also reproduced
the original write failure against the installed Windows runtime and passes
against the rebuilt runtime, including private ACLs, replacement, removal and
refusal to rewrite unsupported assignments.

The manual bundle updater activated the candidate while retaining the old
release. Explicit rollback restored that release, and a second rollback returned
to the candidate; both release pointers were independently checked. This test
used an installation whose client had not yet been configured, so it does not
establish update recovery of a running mail client.

Fresh disposable Codex profiles received both the real device-code and browser
sign-in handoffs from the bundled native runtime. Each flow was cancelled before
account authorization; subsequent authentication checks remained false. No code,
URL, token or existing account profile was exported. Cleanup passed with retries
for transient Windows database file locks. This establishes handoff and
cancellation, not completion of a person's ChatGPT subscription login.

A further native probe found that the direct backend command runner still gave
PowerShell a console handle. Installer `2bd3d05` applies window hiding to the
remaining captured backend, product, discovery and subscription helper launches.
The native console regression now covers the backend and product runners too;
all four paths pass with captured output and zero console handles.

Both native Windows configuration-helper tests failed against the earlier
runtime because they looked for a Unix launcher. Installer `11a7c3e` resolves
Windows commands through the validated release manifest and uses the native
PATH separator in setup. Linux retains its previous command paths. Both native
post-fix tests pass against the real Windows executable, including preservation
of the standalone configuration and one-time import behavior. The OpenAI
sign-in handoffs and cancellation also pass after the captured-helper changes.

## Guided installation and independent mail evidence

An ordinary Windows user started the documented Quick start from a clean,
recursive source checkout. The unchanged Linux terminal operator made adaptive
menu selections and answered normal prompts. The run acquired and built the
native runtime, completed a live DeepInfra GLM-5.3-Flash/high provider probe,
selected an existing disposable OpenMail inbox, installed OMP from its official
Windows installer, and passed OMP's native credential ACL and live model probe.

That rehearsal stopped before final configuration: concurrent test preparation
filled the VM's system disk, and the decoded failed turn reported ENOSPC.
Owned build artifacts were removed and subsequent candidate preparation moved
to a separate scratch disk. This interrupted run is not a successful complete
installation or mail round trip.

A retry also exposed a Windows SSH input-timing limit in the operator's fixed
masked-field check. Counterfeit credentials reproduced the failure without any
raw credential echo: the full masked value appeared after the check deadline.
Instrumentation showed prompt rendering shortly after Node received the input;
the longer delay preceded input delivery. The operator and its security checks
were not weakened. Running it beside the VM passed three consecutive trials
with a counterfeit value matching the model credential's length; longer input
still failed. This does not establish that the original retry exposed a key.

The retry completed through the normal interface and saved a successful
installation outcome. The operator and secure-input checks remained unchanged.
It reused the selected backend and protected email credential, passed the live
model and OMP probes, synchronized a disposable project, configured the client,
and processed an actual OpenMail request. Independent evidence established:

- The requested file exists in the disposable user's Documents folder with the
  requested marker. An OMP Agent Manager ticket is `closed` with
  `completion_source=native_reply` and a nonempty completion artifact.
- OpenMail delivered the response to the disposable correspondent. The client
  database has no pending row and one processed row with an outbound ID.
- Sign-in startup is enabled. The first attempt to change persistence while the
  old client was running failed; stopping and restarting the client recovered
  it. Windows guidance now specifies this transition explicitly.
- After the concierge and its SSH session exited, an independent fresh SSH
  connection still observed the same running supervisor and client.
- Both complete appended installer trajectories and saved outcome were scanned
  against registered keys and encoded variants; the scan was clean.

The guided run also exposed Windows documentation assumptions about SQLite and
fresh environments. The supplied Node runtime now has an explicit read-only
SQLite inspection recipe, verified against the real state database in Windows
PowerShell. Windows fresh-process instructions retain the native profile and
system variables. OMP guidance explains recovery of a stale release-specific
Bash path, and configuration validation explicitly selects the intended file.

The installer prompt itself had supplied a release-specific model-host path.
Installer `f2f1d8c` now supplies the stable Windows launcher, using the same
resolver as the product adapter. The regression failed against the old native
runtime and passed against the rebuilt candidate; Linux prompt context is
unchanged. This later fix was tested separately from the completed guided run.

## Native live Sendmux continuity

A separate ordinary-user fixture created one disposable Sendmux mailbox with
its scoped credential and used a disposable OpenMail correspondent. Verified
TLS, exact-identity unread-message guards, and an empty baseline preceded
polling. Two authenticated messages mapped to one session with sequence two.
Both replies were independently delivered to the correspondent with the same
stable session reference. The quoted follow-up retained the response ancestry;
the coordinator's second prompt contained only the new contribution.

The native database contains exactly two processed messages and no pending
rows. Two distinct Windows SQLite submission journals retain their attempted
markers and provider email/submission IDs. Both inbound messages are seen.
A repeated poll produced no third response. The project has no tracked-file
changes; its only untracked directory is the runtime's `.machtiani` state.
Sendmux's delivery command reported submission with delivery unconfirmed;
actual receipt was established independently at the correspondent.

One follow-up attempt failed closed with a model-host private-file verification
error before sending. Retrying the same retained message succeeded without a
new session or duplicate reply. A guided turn also encountered a transient
credential-boundary failure and recovered on retry. Thirty subsequent native
ACL checks passed, as did eight instrumented checks during the successful
Sendmux retry. Their cause is not established; these failures are not claimed
fixed, nor is an unverified timeout explanation treated as a diagnosis.

## Disk capacity regression

A later running-client bundle update exhausted the disposable system disk while
staging. The active pointer and running supervisor/client remained unchanged,
and failed staging was removed. Completed test artifacts were retired to make
room. The Windows installer now checks destination capacity before copying,
including allocation rounding and working space for activation and client state.
The native regression covers insufficient/exact capacity, long Unicode paths,
and cyclic junction exclusion without changing any destination files. All six
native filesystem cases pass. Concurrent disk consumption can still defeat a
preflight; existing transactional failure handling remains necessary.

After cleanup, the committed `cbb66d5b` source passed a real native capacity
check against the complete bundle. Its PowerShell update activated the release,
retained the previous release, and restarted the previously running client with
new supervisor and daemon PIDs. Pairing and sign-in persistence remained intact.
An independent SSH status check after the updater exited confirmed it remained
running.

## Remaining validation limits

Windows ARM64 is not established by these Windows 11 x64, current-user tests.
The agreed persistence scope is startup at sign-in and shutdown at sign-out,
matching macOS; operation outside a signed-in session is excluded. Subscription handoff/cancellation is verified, but full
account authorization is not. The completed installation was a recovery run
following the interrupted acquisition, not a new clean-room run of the final
candidate. Authenticode distribution, public Windows downloads, and automatic update
discovery/download remain explicitly excluded.
