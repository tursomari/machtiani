# Native Windows installation validation — 20 September 2026

This follows the historical [bounded proof](RESULTS-2026-09-19.md). The native
installation, lifecycle, and incoming-mail gaps identified there have now been
implemented and exercised in a fresh disposable Windows 11 x64 VM on an isolated WSL test host.
No Windows application was installed or executed on the physical Windows host.
Application tests used the ordinary `DM-WIN-TEST\dmuser` account.

## Source and packaging

The temporary umbrella was rebased onto host main `cfe297fd`; its submodule
bases were DearMachine `8ae72b1`, harness `7e402aa`, and installer `c838fca`.
Primary checkouts were left unchanged. All implementation commits were signed
using the configured SSH signing key.

The final Windows bundle was built inside the VM from committed source snapshot
`f68143b`, with DearMachine `3adcc6c`, harness `2890e61`, and installer `d0dfb3f`.
It used the actual builder, frozen pnpm dependencies, TypeScript compilation,
and workspace materialization. Its native products were rebuilt from those
sources. The installed final release was `9aa64729ee18414c9540052152901cac`.
A subsequent DearMachine change, `c3a429c`, updates only the Nix vendored dependency
hash; it does not change the tested Windows Go implementation. This report and
the final umbrella pin update are also subsequent to that build.

The clean guest initially had no Node, Git, or Bash on PATH. Bundled Node, Git for
Windows/Bash, and ripgrep supplied the runtime. The installation path contained
spaces and Unicode. The distribution uses immutable release directories and a
stable launcher; persistent model-host configuration points to that launcher.

## End-to-end file task

The loopback mailbox served a real DKIM-signed message and captured the reply
without sending external email. Native Machtiani launched OMP 18.2.6 using
DeepInfra `zai-org/GLM-5.3` with high reasoning. Ticket
`20260920T071448-005d3c2b` started a real worker and closed with `worker_artifact`.

The task read `Documents/Dear Machine proof Ω/expenses.csv` and created
`windows summary.txt` in the same ordinary Windows folder. Independent checks

The captured reply reported the saved file.

The earlier minimal Codex follow-up passed one native `codex-yolo` task using

## Issues found and fixed by the VM loop

- Startup control timed out before the daemon's allowed readiness deadline.
  Up/restart now wait for the configured startup window.
- Windows file sharing could prevent daemon status-file cleanup. Readers now
  permit deletion, with a native regression.
- PowerShell 5.1 treated a null replacement-backup argument as an invalid empty
  path. Pointer replacement now uses a real temporary backup.
- PowerShell recursive cleanup failed on long runtime paths and could mask the
  original error. A bundled Node helper validates trees and removes long paths.
- Pending uninstall blocked its own persistence cleanup. The narrow Windows
  cleanup operation remains available for retry.
- Temporary shell jobs killed asynchronous workers. Nested command/temporary
  jobs now preserve normal handoff while retaining cancellation ownership;
  tests also cover native PowerShell descendants requesting breakaway.
- The new Windows named-pipe module changed Go vendoring. The Nix hash was
  refreshed and the full Nix checks passed.

Windows delayed startup applications after sign-in. The final reboot changed
the observed boot time from `06:13:57.5Z` to `07:31:31.5Z`. Dear Machine started
without an SSH `up` command, recovered while the separately launched fixture
was not yet listening, and then polled successfully. Independent control
sessions verified the running client before testing restart and forced recovery.

## Release boundaries

This is native Windows x64 support through a prepared bundle and manual bundle
updates. An automatic Windows distribution/update channel and Authenticode
signatures have not been published. Git commit signatures do not substitute for
executable signing. Windows ARM64, pre-sign-in startup, SSH-session detachment,
confined Bash/Codex sandbox guarantees, and power-loss durability are not claimed.
Sendmux remains unavailable on Windows pending its directory durability barrier.

Non-secret evidence includes native test/build logs, source revision metadata,
product hashes, the signed synthetic message and local reply, independently
checked CSV/output, reboot/recovery status, and completed-removal receipts.
The exported evidence was scanned against both authorized provider keys before

regressions after the successful live mail task, without repeating paid Codex work.
