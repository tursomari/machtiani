# Native Windows bounded proof — 19 September 2026

Historical bounded proof. See [20 September installation validation](RESULTS-2026-09-20.md) for the subsequent implementation and resolved gaps.

## Result

Native Windows is feasible without replacing the Go client/harness or the
TypeScript installer/concierge. The bounded proof ran in an ordinary-user
Windows 11 Enterprise Evaluation x64 VM on an isolated WSL test host. The target used native
executables, Node, and portable Git Bash; it did not use WSL.

The live task read `expenses.csv` and wrote `résumé summary.txt` under
`%USERPROFILE%\Documents\Dear Machine proof Ω`. Independent checks found
travel 20.00, food 13.00, grand total 33.00, and an unchanged input SHA-256.
The provider was DeepInfra, model `zai-org/GLM-5.3`, reasoning `high`.
`glm-5.3-medium` was not found as a configured alias.

A real VM reboot followed by ordinary-user sign-in started Dear Machine through
its HKCU startup entry. Independent SSH observations confirmed continuing inbox
polls, restart with a new daemon PID, survival after that control session ended,
and clean down. The inbox was a loopback-only fixture; no real email was sent.

## Implementation

- Per-user PowerShell installer, relocatable runtime bundle, and native launchers.
  Tested installation path: `%LOCALAPPDATA%\Dear Machine Ω`.
- Platform-specific Go helpers for private Windows ACLs, file locks, process
  control, job objects, graceful stop notification, and named-pipe supervision.
- HKCU sign-in startup registration with installation ownership checks. No
  administrator permission is needed for application installation or persistence.
- Windows configuration-file replacement and correct SQLite file-URI encoding.
- TypeScript private-file checks and an authenticated local credential bridge;
  Windows executable discovery, plugin file URLs, and Git Bash profile selection.
- Windows-specific native tests and a documented VM proof procedure.

The shared agent/application behavior remains in the existing implementations.
The main new maintenance surface is OS lifecycle/security and distribution
packaging. PowerShell-based ACL checks work but are relatively slow and deserve
review before broad distribution.

## Findings and remaining work

This is not ready to ship or merge as finished Windows support.

The bundle was developed iteratively: pnpm needed an explicit hoisted layout,
workspace junction materialization, and a rejection check for remaining links.
The first PowerShell copy also hit long-path limits; Robocopy fixed that.
The final installed DSH/credential runtime includes repairs rebuilt in place.
A clean, from-scratch run of the final complete bundle builder is still required
before claiming reproducible release packaging. Signing, artifact size/pruning,
updates, rollback, uninstall, and production installation documentation remain.

The native harness's live file task and the client's mailbox lifecycle were
tested separately. Full incoming-email-to-backend execution, the complete guided
installation conversation, interactive IXE, all external agent backends and
mail providers, Windows ARM64, and confined DSH Bash tasks remain outside this
proof. The basic installer/management DSH session uses the existing full-access
installation policy; this does not establish a Windows Bash sandbox.

Sendmux remains unavailable: its directory-creation durability barrier has not
been established for Windows. No power-loss durability claim is made.

Windows OpenSSH terminates its session's descendants. Starting the supervisor
through SSH therefore does not establish desktop detachment; real sign-in
startup did survive independent control sessions and was verified after reboot.
The VM's startup apps took roughly a minute after sign-in to run. Before-sign-in
startup and survival across user logout were not claimed.

A supplemental ConPTY probe received terminal output and the shell's successful
exit event, but its Node/node-pty process remained alive and was explicitly
stopped. This is an unresolved terminal shutdown observation, not a passing
interactive UI gate.

A transient sharing violation removing the daemon PID file was observed during
the deliberately failing mailbox-fixture retries. Successful restart/down later
passed, but cleanup under rapid crash loops should be hardened before release.

## Cleanup and next decision

Dear Machine was stopped, its persistence disabled, fixture startup and user
environment entries removed, and the temporary DeepInfra credential deleted.
The VM was cleanly powered off and its private TPM process stopped. Only
non-secret evidence and the isolated test installation/source remain.

The proof supports a next bounded tranche: make the final packaging repeatable,
finish the native Windows installation flow, and run one real Dear Machine
backend task end to end. Keep this prototype separate from main until those
checks and the normal component/release gates are complete.
